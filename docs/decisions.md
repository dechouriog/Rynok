# Registro de decisiones: iteración de mejoras (2026-11-17)

Decisiones tomadas al llevar las mejoras de calidad, diseño y pruebas sobre la versión desplegada (Entrega 3, commit `7c05dd7`), en la rama `mejoras-demo-defensa`.

| ID   | Decisión                                                                                                                  | Motivo                                                                                                                                                           | Alternativa descartada                                                                |
| ---- | ------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| D-01 | **Conservar `Escrow.sol` y su despliegue en Sepolia** (`0x049BBA87…`) sin cambios                                         | El contrato ya está desplegado, probado (22 pruebas, 100 %) y validado en Sepolia, y su diseño por `(propiedad, vendedor)` es más robusto que otras alternativas | Reemplazar el contrato: obligaría a redesplegar y se perdería la evidencia en Sepolia |
| D-02 | Trabajar en una rama nueva (`mejoras-demo-defensa`), sin push                                                             | No tocar `main` ni el despliegue actual hasta que el equipo revise                                                                                               | Commits directos a `main`                                                             |
| D-03 | `.gitattributes` con LF                                                                                                   | El clon en Windows mezclaba CRLF y LF y ensuciaba los diffs                                                                                                      | —                                                                                     |
| D-04 | **Verificación on-chain fail-closed en producción**                                                                       | Sin `ESCROW_RPC_URL` el backend aceptaba hashes inventados. En desarrollo y pruebas sigue siendo opcional                                                        | Hacerla obligatoria siempre: rompería las pruebas sin nodo                            |
| D-05 | `trust proxy` + rate limiting                                                                                             | Detrás del proxy de Render, sin `trust proxy` todas las peticiones comparten IP y el límite bloquearía a todos                                                   | —                                                                                     |
| D-06 | helmet con `Cross-Origin-Resource-Policy: cross-origin`                                                                   | La web (Vercel) carga imágenes de `/uploads` desde otro origen; la política por defecto de helmet las bloquearía                                                 | Desactivar helmet                                                                     |
| D-07 | CORS restringido a `CORS_ORIGINS` (agregado a `render.yaml`)                                                              | Antes estaba abierto a cualquier origen. **Requiere configurar la URL de Vercel en Render**                                                                      | Mantenerlo abierto                                                                    |
| D-08 | `NODE_ENV=production` en `render.yaml` + `npm ci --include=dev` en el build                                               | Activa las protecciones de producción. Sin `--include=dev`, npm omitiría el CLI de Nest y el build fallaría                                                      | —                                                                                     |
| D-09 | `GET /properties` pasa a responder `{ items, total, page, limit, totalPages }`                                            | Paginación y orden en el servidor. El único consumidor es este frontend (actualizado)                                                                            | Mantener el arreglo plano y paginar en el cliente                                     |
| D-10 | `depositTxHash` único                                                                                                     | Evita registrar dos veces el mismo depósito                                                                                                                      | —                                                                                     |
| D-11 | Relación `EscrowTransaction.property` **sin clave foránea**                                                               | El historial muestra título e imagen y sobrevive si el vendedor elimina después una propiedad ya liquidada                                                       | FK con `ON DELETE CASCADE`: borraría historial                                        |
| D-12 | El estado del listado on-chain no se guarda en la base: el frontend lo lee del contrato (por RPC aunque no haya MetaMask) | Se mantiene el diseño original y no puede desincronizarse                                                                                                        | Columna `listedOnChain` (requeriría endpoints de registro extra)                      |
| D-13 | Sistema de diseño con tokens en `@theme` (Tailwind v4)                                                                    | `tailwind.config.ts` no se cargaba: la paleta azul nunca se aplicó                                                                                               | `@config` hacia el archivo JS                                                         |
| D-14 | `DEMO_PRICE_SCALE` en el seed                                                                                             | Los faucets de Sepolia dan poco ETH; con 0.001 las propiedades demo son comprables                                                                               | Editar precios a mano                                                                 |
| D-15 | oxlint: `oxlint.json` → `.oxlintrc.json`, con `no-explicit-any` en el código (no en pruebas)                              | oxlint 1.x solo carga `.oxlintrc.json`: las reglas nunca se aplicaban                                                                                            | —                                                                                     |
| D-16 | Playwright fijado en 1.65.0                                                                                               | Coincide con el Chromium ya instalado (no se descargan navegadores)                                                                                              | —                                                                                     |
| D-17 | Nombres en español en la UI y en la documentación nueva; README y `test_evidence.md` se mantienen en inglés               | Respeta el idioma que ya tenía cada documento                                                                                                                    | Traducir todo                                                                         |
